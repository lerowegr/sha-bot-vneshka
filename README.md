# Школа Актива 2026 — тест для внешного конкурса

Telegram Mini App: форма участника (ФИО, курс, студбилет, телефон) → 10 вопросов про ША → баллы (0–10) → экран «Спасибо за прохождение» + подписки на медиа и анкета на Участника. Попытка одна: повторное прохождение отклоняется (409), в розыгрыше участвует первый результат.

Один Python-процесс запускает aiogram polling и aiohttp. Aiohttp обслуживает `/api/quiz/complete`, `/healthz` и собранный Vite frontend из `dist/`. SQLite работает через aiosqlite. Production-образ собирается в два этапа: Node.js компилирует интерфейс, затем в итоговый небольшой Python-образ попадают только backend и готовая папка `dist/`.

## Быстрый локальный просмотр в Docker

Для проверки дизайна нужен только Docker с Compose:

```sh
docker compose -f compose.preview.yaml up --build
```

Откройте `http://127.0.0.1:8080`. Preview-конфигурация отключает Telegram polling, поэтому токен и `.env` не нужны. Тест проходится полностью, но пользователь не записывается: в обычном браузере нет подписанного Telegram `initData`.

Остановка:

```sh
docker compose -f compose.preview.yaml down
```

Именованный volume при этом сохраняется. Команда `down -v` удалит его вместе с данными — не используйте её на сервере, если база нужна.

## Запуск на VPS с общим Nginx

На сервере порты `80/443` уже обслуживает контейнер `arkadium-edge-nginx`. Приложение подключается к его внешней Docker-сети `arkadium_shared` под стабильным сетевым именем `sha-2026-quiz-app`.

Скопируйте настройки и заполните `.env`:

```sh
cp .env.example .env
```

Основные параметры:

```dotenv
BOT_TOKEN=токен_бота
BOT_POLLING_ENABLED=true
APP_DOMAIN=ik-miniapp.ru
MINI_APP_URL=https://ik-miniapp.ru
ADMIN_IDS=ваш_telegram_id
```

Убедитесь, что общая сеть и volume базы существуют:

```sh
docker network inspect arkadium_shared >/dev/null
docker volume create sha-2026-quiz-data
```

Запуск проекта:

```sh
docker compose up --build

# Либо в фоне:
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

Приложение публикуется на `127.0.0.1:8080` для диагностики и доступно общему Nginx внутри Docker как `http://sha-2026-quiz-app:8080`. В конфигурации `/root/infra/nginx.conf` нужно добавить виртуальный хост `ik-miniapp.ru`, который проксирует весь трафик на этот адрес. TLS-сертификат обслуживается существующей инфраструктурой Nginx.

Проверка приложения на самом VPS:

```sh
curl http://127.0.0.1:8080/healthz
```

После настройки Nginx:

```sh
curl https://ik-miniapp.ru/healthz
```

Ожидаемый ответ: `{"status": "ok"}`. Тот же HTTPS URL укажите в настройках Mini App у @BotFather.

Для обновления:

```sh
git pull --ff-only
docker compose up --build -d
```

Один `BOT_TOKEN` нельзя одновременно запускать на нескольких серверах.

## Постоянные данные и Docker volume

SQLite, отписки и журнал рассылок находятся в `/app/data/quiz.sqlite3`. Compose подключает туда именованный volume `sha-2026-quiz-data`. Основной `compose.yaml` объявляет его внешним: Compose использует volume, но не управляет его жизненным циклом. Поэтому базу не удалят ни `docker compose down`, ни `docker compose down -v`, ни пересборка контейнеров.

Volume базы создаётся на VPS один раз до первого запуска:

```sh
docker volume create sha-2026-quiz-data
```

`sha-2026-quiz-data` хранит SQLite и объявлен внешним, поэтому Compose не удаляет его вместе с контейнерами.

Останавливать и снова запускать проект безопасно:

```sh
docker compose down
docker compose up --build -d
```

Не выполняйте `docker volume rm sha-2026-quiz-data` и `docker volume prune`, если volume не исключён из удаления: эти команды действуют вне Compose и могут удалить данные вручную.

Проверить volume:

```sh
docker volume inspect sha-2026-quiz-data
```

Создать консистентную резервную копию работающей базы:

```sh
mkdir -p backups
docker compose exec -T app python -c "import sqlite3; s=sqlite3.connect('/app/data/quiz.sqlite3'); d=sqlite3.connect('/app/data/quiz-backup.sqlite3'); s.backup(d); d.close(); s.close()"
docker compose cp app:/app/data/quiz-backup.sqlite3 ./backups/quiz.sqlite3
```

Восстановление выполняйте при остановленном приложении:

```sh
docker compose stop app
docker compose run --rm --no-deps -v "$PWD/backups:/backup:ro" app python -c "from shutil import copyfile; copyfile('/backup/quiz.sqlite3', '/app/data/quiz.sqlite3')"
docker compose start app
```

Перед восстановлением сохраните текущую базу отдельно. Volume не является резервной копией сам по себе: он защищает от пересоздания контейнера, но не от удаления volume, диска или ошибочной записи.

## Загрузка на сервер

Передайте на сервер исходники проекта без `.env`, затем создайте `.env` уже на сервере. Например, через Git:

```sh
git clone <адрес-репозитория> sha-2026-quiz
cd sha-2026-quiz
cp .env.example .env
# заполнить .env
docker volume create sha-2026-quiz-data
docker compose up --build -d
```

Для обновления:

```sh
git pull --ff-only
docker compose up --build -d
```

Не добавляйте `.env` и резервные копии базы в Git. Проверьте `docker compose ps`: сервис `app` должен перейти в состояние `healthy`. Endpoint `/healthz` не содержит секретов и используется только для проверки работы HTTP-сервера.

Один экземпляр приложения должен использовать один `BOT_TOKEN`: Telegram long polling нельзя одновременно запускать для одного бота на двух серверах. При миграции сначала остановите старый контейнер, перенесите резервную копию volume, затем запустите новый.

## Разработка интерфейса

```sh
npm run dev
```

Vite покажет локальный адрес и будет перенаправлять `/api` на порт 8080. В обычном браузере можно пройти весь тест без токена и без запущенного Python. В этом режиме ничего не сохраняется, UI сообщает об этом. В Telegram вызываются `ready()` и `expand()`, учитываются viewport и safe area, работают нативная кнопка «Назад» и тактильный отклик, если версия поддерживает их.

Полный запуск без Docker по-прежнему доступен:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
npm run build
.venv/bin/python -m bot
```

Проект предназначен для собственного Python-хостинга. Привязка к Sites удалена из конфигурации; публикация туда не требуется. Для мероприятия используйте HTTPS-адрес своего aiohttp-сервера.

## Правила результата

Каждый правильный ответ даёт 1 балл. Всего 10 вопросов, счёт 0–10. Правильные ответы в UI не подсвечиваются, в конце показывается только количество баллов. Порядок вариантов перемешивается.

Значения статов — фиксированные шуточные характеристики, не измерения способностей и не процент совпадения. Есть подпись об этом. Ответы хранятся только в памяти страницы. Перезагрузка начинает тест заново. Переход назад позволяет изменить ответ, повторное прохождение начинается с нуля.

## Сохранение и доверие

После подтверждения последнего ответа отправляется ровно:

```json
{"initData":"<Telegram.WebApp.initData>","result":"score_7"}
```

Допустимые результаты: `score_0` … `score_10`. Сервер проверяет HMAC-SHA256 подпись с токеном бота и `auth_date` (по умолчанию не старше часа, допускается до 30 секунд рассогласования в будущее). Поля `user.id` и `user.username` читаются только после проверки. Дублирующиеся поля, неверные типы, неподписанные данные, лишние поля JSON и недопустимые результаты отклоняются. При HMAC-проверке поле `signature`, если присутствует, входит в подписываемую строку; исключается только `hash`.

Подпись подтверждает пользователя, **не честность прохождения**: API получает счёт, а не десять ответов. Изменённый клиент с действующим initData может отправить любой счёт 0–10. Обычный UI отправляет данные только по завершении всех вопросов.

При сетевой ошибке результат остаётся на экране с кнопкой повторного сохранения. При 401 пользователь получает просьбу переоткрыть Mini App. Повторные запросы атомарно обновляют существующую строку; повторные прохождения не увеличивают число участников. Сырые initData, ответы и другая аналитика не сохраняются.

Алгоритм сверялся с [документацией Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app) и валидатором aiogram в тестах.

## Получить участников

База: `data/quiz.sqlite3` (меняется через `QUIZ_DB_PATH`). Таблица создаётся при запуске приложения, режим WAL поддерживает несколько одновременных записей. Публичного endpoint со списком пользователей нет.

```sh
sqlite3 data/quiz.sqlite3 'SELECT COUNT(*) FROM quiz_users;'
sqlite3 -header -column data/quiz.sqlite3 'SELECT telegram_user_id, telegram_username, result, completed_at FROM quiz_users ORDER BY completed_at DESC;'
```

Есть также асинхронные методы `QuizDatabase.count()` и `participants()`.

## Админка и аналитика

Администратор из `ADMIN_IDS` отправляет `/admin` **в личном чате с ботом**. Все сообщения и callback-кнопки проверяют Telegram ID отправителя и тип чата. В группах админка недоступна. Дополнительная регистрация и веб-панель не нужны.

В меню:

- **Статистика** (`/stats`): число уникальных завершивших тест; число и процент по каждому из пяти направлений; число не отписавшихся получателей; число отписавшихся среди участников.
- **Участники — CSV** (`/participants`): Telegram ID, username при наличии, последнее направление, дата последнего завершения в UTC. Файл выдаётся только администратору.
- **Написать рассылку** (`/broadcast`): ввод текста → предпросмотр → число получателей → отдельная кнопка подтверждения отправки.
- **Мои последние рассылки**: пять последних кампаний текущего администратора с датой, состоянием и итогами отправки. Этот журнал сохраняется после перезапуска.

Повторное прохождение обновляет строку, поэтому статистика показывает уникальных людей и их **последние** результаты. История попыток, ответы на отдельные вопросы, посещения Mini App, незавершённые тесты, конверсия, переходы в канал и прочтения сообщений не собираются. Запуск `/start` без завершения теста не добавляет человека в список рассылки.

## Рассылка об отборе в ИК

1. `/admin` → «Написать рассылку» или `/broadcast`.
2. Отправить боту непустой текст до лимита Telegram 4096 UTF-16 единиц (некоторые эмодзи занимают две). Ссылки и Telegram-форматирование сохраняются. Вложения пока не поддерживаются.
3. Проверить отдельное сообщение-предпросмотр и число получателей.
4. Нажать **«Отправить участникам (N)»**. До этого никакой рассылки участникам нет. Для правки — снова `/broadcast` и новый текст; старый черновик перестаёт действовать.
5. Дождаться отчёта: принято Telegram, заблокирован бот/нет права писать, ошибки, неизвестный исход, пропущено, осталось.

Список получателей фиксируется при предпросмотре: только завершившие тест и не отписавшиеся. Новые участники не попадут в уже подготовленную кампанию. Отписка после предпросмотра учитывается перед отправкой. `/stop` отключает уведомления, `/subscribe` включает их снова; повторный тест и `/start` **не отменяют отписку**. Кнопка отмены и `/cancel` останавливают оставшуюся часть своей рассылки; уже отправленные сообщения и запрос, который уже ушёл в Telegram, не отзываются.

Пользователь должен ранее начать диалог с ботом или дать ему право писать. Наличие ID само по себе не гарантирует доступ: запуск Mini App по отдельной ссылке может не разрешать сообщения, а участник может заблокировать бота позже. Такие случаи отражаются в отчёте. Статус «принято Telegram» означает успешный ответ Bot API, **не доставку на устройство и не прочтение**.

Отправка идёт в фоне того же Python-процесса, примерно до 10 сообщений в секунду, с ожиданием `retry_after` при ограничениях Telegram и максимум тремя попытками. Платные рассылки не включаются. Двойное нажатие кнопки не запускает кампанию повторно; одновременно допускается одна активная кампания. Черновик привязан к создавшему его админу.

Таблица `quiz_users` остаётся с прежними четырьмя полями. Добавлены небольшие служебные таблицы `broadcast_opt_outs`, `broadcasts`, `broadcast_recipients` в **том же SQLite**. Они нужны для отписок, сохранения текстов/форматирования/автора кампании и итогов отправки. Обновление схемы происходит автоматически, существующие участники сохраняются.

При сетевой ошибке исход отправки бывает неизвестен: повтор мог бы создать дубль, поэтому такой запрос автоматически не повторяется. При остановке процесса активная кампания отмечается как прерванная, незавершённые отправки — как неизвестные. После перезапуска автоматического продолжения нет; итоги доступны в журнале. Новая рассылка — новая кампания на весь новый список; это **не повтор только неудачных отправок**.

Лимиты сверены с [Telegram Bots FAQ](https://core.telegram.org/bots/faq#how-do-i-avoid-hitting-limits).

## Проверки

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
npm test
npm run build
.venv/bin/python -m pytest -q
```

Тесты проверяют все комбинации подсчёта, контракт frontend API, отсутствие записи в браузерном режиме, отказ при подделке/просрочке подписи, повторную и параллельную запись, HTTP-валидацию и защиту файлов вне `dist/`.

Тесты админки проверяют доступ по ID и типу чата, предпросмотр без рассылки, подтверждение, защиту от повторного запуска, отписки, статистику, CSV, ограничения Telegram, ошибки отправки и восстановление журнала после перезапуска. В тестах Telegram API заменён имитацией; реальным пользователям сообщения не отправляются.

Реальный запуск в Telegram требует вашего токена, HTTPS-хоста и проверки на устройстве. В этой реализации не выполнялась визуальная браузерная проверка. Необязательный WebMCP включается только при поддержке браузером; в стандартном Telegram WebView он не нужен.
